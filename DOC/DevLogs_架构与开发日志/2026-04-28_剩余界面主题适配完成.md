**文件**: `FocusFlow_App/app/src/main/java/com/example/focusflow/ui/theme/AppTheme.kt`

新增两个关键方法以支持传统 Android Views（用于 LockOverlayService）：

```kotlin
/**
 * 同步获取当前主题颜色（用于 Service 等非 Compose 环境）
 */
fun getCurrentColors(context: Context): AppColors {
    // 使用 runBlocking 同步读取 DataStore
    val preferences = kotlinx.coroutines.runBlocking {
        dataStore.data.first()
    }
    val ordinal = preferences[PreferencesKeys.THEME_MODE] ?: 0
    val themeMode = ThemeMode.fromOrdinal(ordinal)
    
    // 根据主题模式返回对应颜色
    when (themeMode) {
        ThemeMode.FOLLOW_SYSTEM -> {
            val isSystemDark = (context.resources.configuration.uiMode and 
                android.content.res.Configuration.UI_MODE_NIGHT_MASK) == 
                android.content.res.Configuration.UI_MODE_NIGHT_YES
            if (isSystemDark) DarkAppColors else LightAppColors
        }
        ThemeMode.FORCE_DARK -> DarkAppColors
        ThemeMode.FORCE_LIGHT -> LightAppColors
    }
}

/**
 * 获取指定颜色类型的 Android Color Int（用于传统 View 系统）
 */
fun getColorInt(context: Context, colorType: String): Int {
    val appColors = getCurrentColors(context)
    val color = when (colorType) {
        "primary" -> appColors.primary
        "bgDeep" -> appColors.bgDeep
        "cardBg" -> appColors.cardBg
        "textMain" -> appColors.textMain
        "textSub" -> appColors.textSub
        else -> appColors.primary
    }
    
    // 将 Compose Color 转换为 Android Color Int
    return android.graphics.Color.argb(
        (color.alpha * 255).toInt(),
        (color.red * 255).toInt(),
        (color.green * 255).toInt(),
        (color.blue * 255).toInt()
    )
}
```

**技术创新点**：
- 使用 `runBlocking` 在非协程环境中同步读取 DataStore
- 支持 `FOLLOW_SYSTEM` 模式，自动检测系统深色模式
- 提供 Compose Color 到 Android Color Int 的转换

#### 3.2 主题动态更新机制

```kotlin
private val themeChangeReceiver = object : BroadcastReceiver() {
    override fun onReceive(context: Context?, intent: Intent?) {
        if (intent?.action == "com.example.focusflow.action.THEME_CHANGED") {
            Log.d(TAG, "收到主题变化广播，重建悬浮窗视图")
            recreateOverlayView()
        }
    }
}

override fun onCreate() {
    super.onCreate()
    // 注册主题变化广播接收器
    val filter = IntentFilter("com.example.focusflow.action.THEME_CHANGED")
    registerReceiver(themeChangeReceiver, filter, RECEIVER_NOT_EXPORTED)
}

private fun recreateOverlayView() {
    // 移除旧视图
    overlayView?.let { windowManager.removeView(it) }
    
    // 重新创建视图（会自动获取最新主题颜色）
    overlayView = createCapsuleOverlayView()
    windowManager.addView(overlayView, overlayParams)
    
    Log.d(TAG, "悬浮窗视图已重建，主题已更新")
}
```

**技术创新点**：
- 使用广播机制实现主题变化通知
- 视图重建保留当前专注状态
- 避免闪烁和卡顿

## 技术难点与解决方案

### 难点 1: LockOverlayService 使用传统 Views

**问题**: LockOverlayService 使用传统 Android Views，无法直接使用 Compose 的 `LocalAppColors`

**解决方案**:
1. 在 ThemeManager 中添加 `getCurrentColors()` 同步方法
2. 使用 `runBlocking` 在非协程环境中读取 DataStore
3. 提供 `getColorInt()` 方法将 Compose Color 转换为 Android Color Int

### 难点 2: 主题动态更新

**问题**: 锁屏界面在后台运行，无法自动感知主题变化

**解决方案**:
1. 在 `ThemeManager.setThemeMode()` 中发送广播
2. 在 LockOverlayService 中注册广播接收器
3. 收到广播后重建悬浮窗视图

### 难点 3: CapsuleHatchView 内部硬编码颜色

**问题**: CapsuleHatchView 是自定义 View，内部有硬编码的深色背景色

**解决方案**:
1. 添加 `setThemeColors()` 方法支持动态设置颜色
2. 在 LockOverlayService 创建视图时调用此方法
3. 触发 `invalidate()` 重绘
